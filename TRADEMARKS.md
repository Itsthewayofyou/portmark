## What this policy is protecting

Portmark is a security boundary. The value of the name is that somebody reading "Portmark" can rely
on it meaning the runtime that was actually built, reviewed and tested here. A modified build that
still calls itself Portmark transfers that trust onto code nobody here has seen.

So the rule is about **identity**, not about control of the software. You may change the software
freely. You may not present the changed thing as though it were this one.

## You may do these without asking

  For example: "built on Portmark", "works with Portmark", "Portmark-compatible".
* Use the name in documentation, articles, talks, courses, reviews and comparisons.
* Use the name in a package or module name that describes an integration rather than claiming to be
  Portmark itself — for example `portmark-django-adapter`, not `portmark-runtime`.
* Redistribute **unmodified** Portmark under its name.
* Link to the Portmark repository and use the logo in that link, unmodified.

You may run a service built on Portmark, subject to the license in LICENSE. Name it after yourself,
not after Portmark. "Acme Agent Gateway, built on Portmark" is fine. "Portmark Cloud" is not.
